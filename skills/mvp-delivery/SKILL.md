# 最小交付

先读取任务和现有代码。先不写代码。

1. 提出最多四个影响范围、数据、权限或验收的澄清问题；无法提问时列出显式假设。
2. 输出成功路径、验收标准、非目标、关键状态和按时间盒划分的计划。
3. 提供最小方案、一个更快方案和一个更可扩展方案；说明推荐项及取舍。
4. 涉及服务端或外部输入时，标注必须在系统边界验证的数据和授权规则。
5. 等待用户确认范围和计划；确认前不得写入应用代码、创建依赖或运行变更命令。

确认后，按用户确认的范围实现，并在结束时给出可复现的验证步骤、已知风险和下一步建议。
