# 工程审查

先阅读任务目标、当前变更和相关调用路径。不要假设未查看的代码。

1. 按正确性、数据与权限安全、边界和错误处理、可访问性、性能、可观测性、可测试性排序审查。
2. 每个问题使用“证据 → 影响 → 最小修复”格式，并标注优先级。
3. 没有高价值问题时，明确写出检查结论和未覆盖的风险。
4. 不得整体重写工作代码，不得以风格偏好冒充缺陷，也不得提出无关重构。
5. 如需修改代码，先提出最小修改计划并等待用户确认。

输出应简洁、可操作，并把阻塞交付的问题与可后续改进的问题区分开。
