# 调试闭环

先收集证据，不要猜测修复。

1. 记录预期行为、实际行为、环境、触发步骤和最小复现证据。
2. 阅读错误信息和近期变化；从输入到输出追踪状态与数据流。
3. 提出按可能性排序的单一假设，并给出验证每个假设的最小观测方式。
4. 定位根因后，提出最小修复、回归测试和验证命令；等待用户确认后才改代码。
5. 完成后报告根因、修复、验证结果和仍然存在的风险。

不得基于猜测改代码，不得吞掉错误，不得把多个不相关修复捆绑在一起。
