# 功能切片

先阅读受影响的代码和项目约定。先不修改代码。

1. 定位入口、相邻实现、数据流和测试方式；列出准备改动的文件及职责。
2. 定义一条从用户操作到可见结果的最小垂直切片；只有任务需要时才覆盖 API 和持久化。
3. 写明成功、loading、empty、error 状态，以及输入校验、权限、错误反馈和回归测试。
4. 明确不改动的范围；避免无关重构、额外依赖和静默失败。
5. 等待用户确认文件范围和实施计划；确认前不得写入应用代码或运行变更命令。

确认后按最小切片实施。完成后验证主链路和每个相关异常状态，并说明运行命令、验证结果和剩余边界。
